# Отчёты новостей и медиа по расписанию

Во вкладке **Новости и медиа → Отчёты** создайте расписание с названием, поисковыми запросами, частотой и временем отправки. Каждый запрос вводится с новой строки и получает отдельный отчёт. По умолчанию доступны три запроса в расписании и пять расписаний на аккаунт.

Используется существующая аналитика `NewsMarketingAnalyticsService::analyze`: бренд и конкуренты, темы и вопросы для контента, площадки для публикаций и присутствие домена в собранной веб-выдаче. HTML формируется существующим шаблоном `reports.news-media-intel.analytics`. Бренд, до трёх конкурентов, домен, язык, фильтр периода, безопасный поиск, выбранные движки и число страниц сохраняются вместе с расписанием и фиксируются в задании перед отправкой в очередь.

## Частота и фильтр периода

- Каждый день, каждые три или семь дней: первый автоматический запуск через выбранное число дней в указанное время, затем с той же частотой.
- Каждый месяц: первого числа следующего месяца в выбранное время, затем первого числа каждого месяца.

Часовой пояс выбирается из списка городов; можно использовать время устройства. По умолчанию используется Москва. Планирование учитывает часовой пояс и переходы летнего времени.

**Частота отправки и период поиска независимы.** Например, можно получать отчёт каждые три дня с фильтром публикаций за месяц. SearXNG не предоставляет точного фильтра «за три дня»: доступны всё время, сутки, неделя, месяц или год, с поддержкой со стороны конкретных движков. Результат описывает выборку на момент фактического поиска, а не полный архив упоминаний за интервал расписания.

JSON содержит `reportSchedule.scheduledFor`, фактический `checkedAt`, часовой пояс, частоту и `metricsBasis: sample_at_check_time`. HTML также показывает параметры расписания. Частичные данные и недоступные движки отмечаются существующей аналитикой; отсутствие веб-выдачи не считается нулевой видимостью домена.

После простоя планировщика пропущенные проверки объединяются в один последний наступивший запуск. Текущие данные не выдаются за исторические снимки.

## Управление и история

Расписание можно приостановить, возобновить или удалить. Возобновление назначает новый первый запуск. Кнопка **Сформировать сейчас** работает и на паузе, создаёт проверку по сохранённым запросам и не сдвигает следующий автоматический запуск.

Готовые отчёты хранятся в БД и доступны владельцу для просмотра, скачивания HTML и JSON. Удаление расписания останавливает проверки и сохраняет готовую историю. Просмотр и повторное скачивание не запускают поиск и не зависят от временного cache обычной вкладки аналитики. Списки не раскрывают сохранённые данные отчёта и внутренние токены очереди.

Нужен активный аккаунт с подтверждённой почтой. Модуль остаётся бесплатным: расписания не вводят новых списаний дневной квоты. Запросы проходят те же ограничения поисковых команд и пользовательских фильтров, что и обычная аналитика. Пользователь не может указать адрес SearXNG: он задаётся администратором через конфигурацию Laravel.

## Telegram-бот

Привяжите аккаунт на `/settings/telegram`, разрешите доставку файлов в настройках бота и включите отправку в Telegram в расписании. Готовый HTML отправляется существующим outbox с типом `news_media_report`. В меню бота доступны готовые отчёты новостей в HTML/JSON.

Перед доставкой и повторно после подготовки документа проверяются владелец, актуальная привязка, состояние аккаунта и согласие на автоматическую отправку. Ошибка доставки не отменяет готовый отчёт на сайте и не вызывает повторный поиск. Worker очереди `TELEGRAM_BOT_QUEUE` должен работать, как и для остальных модулей.

## Настройка очереди

SearXNG уже развёрнут на VPS; локальная установка для этой функции не нужна. Laravel и worker должны иметь доступ к адресу `OSINT_NEWS_MEDIA_SEARXNG_BASE_URL`. Для всех сценариев аналитики включите JSON, категории `news` и `general`, а также нужные движки на существующем SearXNG.

Примените миграции и соберите клиент/SSR:

```bash
php artisan migrate --force
npm run build
```

Настройки находятся в `config/news_media_reports.php`:

```dotenv
NEWS_MEDIA_REPORTS_QUEUE_CONNECTION=news-media-reports-database
NEWS_MEDIA_REPORTS_QUEUE=news-media-reports
NEWS_MEDIA_REPORTS_TIMEZONE=Europe/Moscow
NEWS_MEDIA_REPORTS_TIMEOUT=120
NEWS_MEDIA_REPORTS_RETRY_AFTER=180
NEWS_MEDIA_REPORTS_LEASE_SECONDS=300
```

Для Redis используйте `news-media-reports-redis`. Отдельные connections в `config/queue.php` сохраняют настройки остальных очередей. `retry_after` и lease должны превышать timeout задания; cache должен поддерживать атомарные блокировки и быть общим для production workers.

```bash
php artisan queue:work news-media-reports-database --queue=news-media-reports --timeout=120 --tries=1 --sleep=1 --max-time=3600
php artisan schedule:list
```

Worker должен постоянно работать под Supervisor/systemd и перезапускаться после выхода. Для локального запуска можно убрать `--max-time=3600`. После изменения кода и конфигурации перезапустите workers и обновите config cache.

Команда `news-media:reports-maintain` зарегистрирована каждую минуту. Она создаёт наступившие задания, восстанавливает прерванные попытки и повторяет уведомления о готовых отчётах. Действующий Laravel scheduler обслуживает её без отдельного cron: на сервере нужен `php artisan schedule:run` каждую минуту, локально — `php artisan schedule:work`.

Количество попыток генерации хранится в БД и по умолчанию равно трём. Временные сетевые ошибки повторяются с задержкой; токены и блокировки не дают устаревшему worker перезаписать результат нового запуска. Готовые снимки при восстановлении очереди не пересчитываются.
