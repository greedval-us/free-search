# Telegram Bot

Изолированный модуль сайта на **defstudio/telegraph**. Не использует MadelineProto, сервисный Telegram-аккаунт или сессии парсеров. По умолчанию выключен и не требует токена для запуска сайта.

## Возможности

- Inline-меню, помощь, списки собственных выгрузок парсеров с пагинацией.
- Повторная отправка JSON/XLSX четырёх парсеров через существующие application services и Excel builders.
- Персональные уведомления из существующего database-канала сайта.
- Автоотправка новых выгрузок парсеров и административные объявления по отдельному согласию.
- Кнопка WebApp, открывающая рабочее пространство.
- Настройки привязки, языка RU/EN и подписок: /settings/telegram.

WebApp открывает обычный сайт с его авторизацией и 2FA. Автоматический вход по Telegram ID не реализован. Mini App SSO потребует отдельного сценария с серверной проверкой подписанного initData, срока действия и повторного использования.

## Слои

Бизнес-логика находится в app/Modules/TelegramBot:

| Слой | Ответственность |
| --- | --- |
| Domain | Контракты BotAction, BotTransport, ArtifactProvider; DTO экранов, кнопок, документов и контекста |
| Application | Привязка, настройки, маршрутизация разрешённых действий, сборка меню, outbox |
| Infrastructure | TelegraphTransport, адаптеры существующих экспортёров и локализации, подписчик на события сайта |
| Jobs | Фоновая обработка обновлений и отправка документов/сообщений |
| Console | Настройка webhook, рассылка, восстановление очереди и очистка |

HTTP-адаптеры находятся в app/Http/{Controllers,Requests,Middleware}/TelegramBot, маршруты в routes/telegram-bot.php, регистрация в app/Providers/TelegramBotServiceProvider.php. Это соответствует архитектурным тестам проекта: модуль не зависит от App\Http и не формирует HTTP-ответы.

BotTransport реализован через TelegraphBot, TelegraphChat, Keyboard и Button пакета. Собственного HTTP-клиента Telegram нет. Входящий webhook отдельный: это позволяет не помещать токен бота в URL и не разрешать вызов произвольных PHP-методов из callback_data.

Сайт не вызывает бот из контроллеров. Интеграция подписана на NotificationSent и изменение статуса ParserRun. Сервис отчётов не связан с ботом. Ошибки необязательного канала не должны срывать основную операцию сайта.

## Привязка и доступ

1. Авторизованный пользователь с подтверждённой почтой создаёт одноразовую ссылку.
2. В БД сохраняется только SHA-256 токена; срок жизни по умолчанию 10 минут.
3. Пользователь открывает ссылку и нажимает Start. Webhook принимает только личный чат, где chat.id совпадает с from.id.
4. Бот фиксирует Telegram ID в заявке, но ещё не связывает аккаунт.
5. Пользователь возвращается на сайт, проверяет ID и явно подтверждает связь.

Один Telegram ID соответствует одному аккаунту сайта. Старое значение users.telegram_id само по себе не даёт доступа: требуется подтверждённая запись telegram_bot_links. Бот не принимает ID пользователя сайта, путь к файлу или имя Blade-шаблона из callback.

Права, актуальная связь, блокировка аккаунта и согласие проверяются при отправке, а для документов повторно после генерации. Отвязка удаляет ожидающие доставки. Уже загруженный в Telegram документ отозвать этой операцией невозможно.

Окончательная привязка и отвязка создают непрочитанные уведомления безопасности на сайте со ссылкой на настройки Telegram и ID связанного аккаунта. Запись уведомления входит в ту же транзакцию, что и изменение связи. Создание ссылки, подтверждение в боте без подтверждения на сайте и повторная отвязка без активной связи уведомлений не создают. Тексты берутся из локализации RU/EN при отображении. После отвязки уведомление остаётся только на сайте и не отправляется в отключённый чат.

## Данные и доставка

- telegram_bot_links: проверенные связи и настройки согласия.
- telegram_bot_link_requests: временные заявки, хеши вместо исходных токенов.
- telegram_bot_deliveries: outbox, состояния pending/sent/skipped/failed, без файловых payload.
- telegram_bot_reports: устаревшая таблица метаданных. Новые записи не создаются; просроченные записи очищает планировщик. Применённая миграция сохранена без изменений.
- telegraph_bots / telegraph_chats: штатные таблицы пакета. Токен хранится в таблице пакета; защищайте доступ к БД и резервным копиям.

Уведомления в outbox представлены ID записи сайта. Для объявлений сохраняется текст. Выгрузки остаются в существующем private storage; JSON не переносится в таблицы бота.

Срок парсерных файлов остаётся прежним: 7 дней. Аналитика и отчёты доступны на сайте; бот не ведёт их каталог и не отправляет HTML. Старые кнопки отчётов обрабатываются как недоступный файл, а ожидающие доставки отчётов получают статус skipped без отправки. После обновления кода нужно пересобрать кэш конфигурации и перезапустить worker; новое меню можно получить командой /start.

Документы собираются во временном private-каталоге и удаляются после попытки отправки. Ограничение размера настраивается в config/telegram_bot.php, по умолчанию 49 MiB. При истечении срока или превышении размера пользователь получает пояснение и ссылку на сайт. Серверная очистка **не удаляет копии из Telegram**.

Очередь использует общий лимит скорости, последовательное выполнение для одного Telegram ID, retry_after от Telegram и ограниченное окно повторов. После ответа 429 задания освобождают worker, а не вызывают sleep. Планировщик восстанавливает pending-доставки после сбоя очереди.

Повторные события дедуплицируются, выполненные задания повторно не отправляются. Абсолютная exactly-once доставка недостижима: если Telegram принял сообщение, а соединение оборвалось до подтверждения, повтор может создать копию.

## Подключение на VPS

Эти команды выполняются после деплоя. Локально настоящий бот не создавался, webhook не регистрировался.

~~~bash
composer install --no-dev --optimize-autoloader
php artisan migrate --force
npm ci
npm run build
php artisan telegraph:new-bot
~~~

В мастере Telegraph введите токен BotFather. Не соглашайтесь на стандартную регистрацию webhook: у модуля собственная команда. Не создавайте групповой чат. Найдите числовой ID созданной записи telegraph_bots.

Настройте .env, не добавляя секреты в Git:

~~~dotenv
APP_URL=https://uraboros.online
TELEGRAM_BOT_ENABLED=true
TELEGRAM_BOT_ID=1
TELEGRAM_BOT_USERNAME=your_bot_username
TELEGRAPH_WEBHOOK_SECRET=replace_with_random_secret
TELEGRAM_BOT_QUEUE_CONNECTION=database
TELEGRAM_BOT_QUEUE=telegram-bot
~~~

Замените ID и username реальными значениями. Секрет заголовка должен быть случайным, длиной 32-256 символов, из букв, цифр, дефиса и подчёркивания. Генерация на сервере:

~~~bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
~~~

Настройте Supervisor/systemd для постоянно работающего worker этой очереди. Пример команды, не готовая конфигурация сервиса:

~~~bash
php artisan queue:work database --queue=telegram-bot --sleep=1 --timeout=120 --tries=0 --max-time=3600
~~~

Используйте системного пользователя проекта, не root. Нужен доступ к private storage и общей БД/кэшу. retry_after соединения должен быть больше timeout задания; штатные 150 и 120 секунд подходят. При увеличении timeout согласуйте retry_after и stopwaitsecs Supervisor. Для нескольких worker нужен общий cache store с атомарными locks, не array. Не используйте sync, deferred или background для очереди бота.

Если уже настроен ежеминутный Laravel scheduler, ещё один cron не добавляйте. Модуль сам регистрирует восстановление доставки каждую минуту и ежедневную очистку в 04:30 (время задаётся конфигурацией).

После настройки:

~~~bash
php artisan config:cache
php artisan telegram-bot:configure --check
php artisan telegram-bot:configure
php artisan queue:restart
php artisan schedule:list
~~~

Только команда без --check вызывает Telegram и регистрирует HTTPS endpoint /integrations/telegram-bot/webhook с секретным заголовком. Не запускайте telegraph:set-webhook для этого бота. Убедитесь, что reverse proxy пропускает X-Telegram-Bot-Api-Secret-Token и не пишет заголовки/тела webhook в логи.

Финальная проверка с настоящим токеном: привязать аккаунт, подтвердить ID, открыть inline-меню, скачать свою выгрузку, включить уведомления и проверить доставку. Проверка --check не подтверждает работоспособность токена, DNS, worker или доступность Telegram.

## Объявления

~~~bash
php artisan telegram-bot:broadcast "Update announcement" --locale=en --dry-run
php artisan telegram-bot:broadcast "Update announcement" --locale=en --confirm
~~~

Без --confirm отправки нет. Получатели только явно включившие объявления; доступ повторно проверяется worker. Для RU и EN запускайте отдельные кампании с соответствующим текстом. Каждая подтверждённая команда создаёт новую кампанию.

## Расширение

Новое действие: реализовать BotAction, зарегистрировать класс в telegram_bot.actions, добавить кнопку с его key в telegram_bot.menus и перевод в lang/{ru,en}/telegram_bot.php. Значения callback_data ограничены 64 байтами; передавайте короткие ID, не JSON или пользовательские данные.

Новый тип документа: реализовать ArtifactProvider с обязательной проверкой владельца и срока, зарегистрировать в artifact_providers, добавить меню. Для нового вида автоматической доставки также явно определить согласие в BotAccess::allowsDelivery и обработку задания, не открывать доступ по умолчанию. Эта политика проверяется перед постановкой в очередь и повторно перед отправкой; outbox отвечает только за запись, дедупликацию и повторную постановку заданий.

## Проверки

~~~bash
php artisan test --filter=TelegramBot
npm run test:unit
npm run quality:check
~~~

Тесты используют SQLite in-memory, Storage::fake, Queue::fake и Telegraph::fake, без внешних Telegram-запросов. Проверяются привязка, чужие и просроченные файлы, настоящая генерация JSON/XLSX, opt-in, очередь, дедупликация, webhook, безопасная обработка ошибок и отключение устаревшей доставки отчётов без изменения отчётов сайта.
