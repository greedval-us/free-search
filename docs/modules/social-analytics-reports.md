# Отчёты Bluesky и Mastodon по расписанию

Во вкладке **Bluesky → Отчёты** или **Mastodon → Отчёты** создайте расписание: название, аккаунты с новой строки, частота, время и часовой пояс. Интерфейс и управление совпадают с Telegram и YouTube. По умолчанию доступны три аккаунта в расписании и пять расписаний на пользователя.

Для Bluesky подходят `name.bsky.social`, `@name.bsky.social`, DID и `https://bsky.app/profile/name.bsky.social`. Для Mastodon — `name@server`, `@name@server`, ссылки профиля `https://server/@name` / `https://server/users/name`. Локальное имя Mastodon относится к настроенному серверу.

| Частота | Период отчёта |
| --- | --- |
| Каждый день | Предыдущий завершённый день |
| Каждые три дня | Три предыдущих завершённых дня |
| Каждые семь дней | Семь предыдущих завершённых дней |
| Каждый месяц | Предыдущий календарный месяц, запуск первого числа |

Первый запуск назначается через выбранное число дней, для месяца — на первое число следующего месяца. Часовой пояс выбирается из списка городов или определяется кнопкой по устройству; по умолчанию Москва. Границы периода фиксируются до очереди, учитывают часовой пояс и летнее время. Дневная статистика использует тот же пояс.

Расписание можно приостановить, возобновить и удалить. **Сформировать сейчас** собирает предыдущий завершённый период, работает при паузе и не сдвигает автоматический запуск. После удаления расписания готовые отчёты остаются в истории. Просмотр и скачивание HTML/JSON используют сохранённый снимок БД, не требуют повторного запроса к источнику и не расходуют квоту.

## Данные

Сохранённые отчёты используют существующие построители и HTML-шаблоны аналитики соответствующих модулей. К отчёту добавляются период, часовой пояс и пояснение данных. Лайки, репосты/бусты и ответы — текущие накопленные счётчики публикаций, созданных в периоде, а не прирост реакций за эти дни.

Bluesky получает публичные профили и ленты через фиксированный `https://public.api.bsky.app`, без входа в аккаунт. Сбор исключает публикации других авторов, появившиеся в ленте из-за репостов. Если отдельный счётчик не возвращён, он показывается как «Нет данных». Существующие поиск, парсер и интерактивная аналитика продолжают использовать свою конфигурацию. [Публичный Bluesky API](https://docs.bsky.app/docs/advanced-guides/api-directory).

Mastodon использует `MASTODON_API_BASE_URL` и при необходимости `MASTODON_API_TOKEN`. Отчёт включает доступные этому серверу публичные публикации и публикации по ссылке, исключает бусты, приватные и прямые сообщения. Федерация и кэш сервера ограничивают доступную удалённую историю и известные счётчики: снимок не обещает глобальную полноту Mastodon. URL введённого профиля нормализуется в адрес аккаунта; сетевые запросы остаются на настроенном сервере. [Account statuses API](https://docs.joinmastodon.org/methods/accounts/#statuses), [поля Status](https://docs.joinmastodon.org/entities/Status/).

Сбор читает все доступные страницы истории и затем фильтрует публикации по точному периоду. По умолчанию предел — 100 страниц: Bluesky до 100 записей на страницу, Mastodon до 40. Превышение предела или зацикливание страниц даёт ошибку; частичный результат не сохраняется как готовый. Для больших аккаунтов увеличьте `*_ANALYTICS_REPORTS_FETCH_MAX_PAGES` с учётом лимитов API и времени worker. Временные ошибки повторяются до трёх раз.

Формирование одного отчёта по одному аккаунту расходует одну единицу `bluesky.analytics` или `mastodon.analytics`. Повторная попытка не списывает её снова; неуспешное формирование возвращает списание в тот же день. Права и владелец проверяются при запуске, сохранении результата, просмотре и отправке.

## Telegram-бот

Включите отправку в бота в расписании, привяжите аккаунт на `/settings/telegram` и включите автоматическую доставку файлов. Готовый HTML отправится через существующий outbox. Меню **Аналитические отчёты Bluesky** и **Аналитические отчёты Mastodon** позволяет повторно получить HTML/JSON вручную. Актуальные разрешения проверяются перед загрузкой, включая изменения во время формирования документа; outbox предотвращает дубли.

## Запуск

```bash
php artisan migrate --force
npm run build
```

```dotenv
BLUESKY_ANALYTICS_REPORTS_QUEUE_CONNECTION=database
BLUESKY_ANALYTICS_REPORTS_QUEUE=bluesky-analytics-reports
BLUESKY_ANALYTICS_REPORTS_TIMEZONE=Europe/Moscow
BLUESKY_ANALYTICS_REPORTS_FETCH_MAX_PAGES=100
MASTODON_ANALYTICS_REPORTS_QUEUE_CONNECTION=database
MASTODON_ANALYTICS_REPORTS_QUEUE=mastodon-analytics-reports
MASTODON_ANALYTICS_REPORTS_TIMEZONE=Europe/Moscow
MASTODON_ANALYTICS_REPORTS_FETCH_MAX_PAGES=100
```

Допустимы долговечные очереди `database` и `redis`, `retry_after` должен превышать timeout 120 секунд. Cache должен поддерживать атомарные блокировки. Лимиты аккаунтов и расписаний находятся в `config/bluesky_analytics_reports.php` и `config/mastodon_analytics_reports.php`.

```bash
php artisan queue:work database --queue=bluesky-analytics-reports,mastodon-analytics-reports --timeout=120 --tries=1 --sleep=1 --max-time=3600
php artisan schedule:list
```

Worker запускается постоянно под Supervisor/systemd; после обновления кода и конфигурации workers перезапускаются. Scheduler вызывает `bluesky:analytics-reports-maintain` и `mastodon:analytics-reports-maintain` каждую минуту. На сервере нужен `schedule:run` каждую минуту; локально можно использовать `php artisan schedule:work` и worker без `--max-time`.
