# Отчёты аналитики YouTube по расписанию

Во вкладке **YouTube → Отчёты** создайте расписание с названием, публичными каналами, интервалом и временем. Принимаются `@handle`, ID канала `UC…` и ссылки `youtube.com/@handle` / `youtube.com/channel/UC…`. Каждый канал вводится с новой строки и получает отдельный отчёт. По умолчанию можно выбрать до трёх каналов и сохранить пять расписаний; пределы задаются в `config/youtube_analytics_reports.php`.

- Каждый день: предыдущий завершённый день.
- Каждые три дня: три предыдущих завершённых дня.
- Каждые семь дней: семь предыдущих завершённых дней.
- Каждый месяц: первого числа, за предыдущий календарный месяц.

Первый запуск через выбранное число дней в заданное время; для месяца — первое число следующего месяца. Часовой пояс выбирается из списка городов со смещением UTC, либо кнопкой «Использовать время устройства». По умолчанию — Москва. Границы дней учитывают летнее время и фиксируются до постановки задания в очередь. Задержка обработки не меняет период.

Можно приостановить, возобновить или удалить расписание. После возобновления назначается новый первый запуск. Удаление прекращает автоматическое формирование, готовая история сохраняется. **Сформировать сейчас** работает и при паузе, собирает предыдущий завершённый период и не сдвигает следующее автоматическое время.

## Данные и сохранённые отчёты

Отчёт выбирает публичные видео, опубликованные за период. Просмотры, лайки и комментарии — накопленные показатели этих видео на момент сбора, а не прирост показателей канала за выбранные дни. Это данные публичного YouTube Data API, не закрытая аналитика владельца из YouTube Studio. Период и пояснение показаны в интерфейсе, HTML и JSON. [Документация статистики видео](https://developers.google.com/youtube/v3/docs/videos).

Если YouTube не возвращает число лайков или комментариев для отдельных видео, недоступные показатели показываются как «Нет данных». JSON содержит количество видео без каждой метрики и сумму известных значений; итог без полного набора не выдаётся за точный ноль.

Список видео собирается через uploads playlist с постраничным чтением; статистика запрашивается пакетами по 50 видео. Это обходит ограничение поиска по каналу в 500 результатов. Даты публикации повторно проверяются, дневная группировка использует часовой пояс расписания. [PlaylistItems API](https://developers.google.com/youtube/v3/docs/playlistItems/list), [ограничения Search API](https://developers.google.com/youtube/v3/docs/search/list).

Чтобы гарантировать полный результат без предположений о порядке публикаций, читается весь доступный uploads playlist. По умолчанию предел — 100 страниц (до 5000 записей канала), включая видео вне периода. Если канал больше, увеличьте `YOUTUBE_ANALYTICS_REPORTS_FETCH_MAX_PAGES` с учётом API quota и времени worker. Превышение предела и зацикливание страниц дают понятную ошибку, частичные данные не выдаются за готовый отчёт. Временные ошибки повторяются до трёх раз.

Готовые снимки хранятся в БД: история, просмотр и скачивание HTML/JSON не зависят от кратковременного кэша и не повторяют запросы YouTube. Каждый новый отчёт по каналу расходует одну единицу дневного лимита `youtube.analytics`. Повтор обработки этого же отчёта не списывает лимит снова. Неуспешное формирование возвращает списание в тот же день. Все операции доступны владельцу с подтверждённой почтой, активным аккаунтом и доступом к аналитике по текущему тарифу.

## Бот

В расписании включите «Также отправлять отчёты в Telegram», привяжите аккаунт на `/settings/telegram` и включите доставку отчётов. Готовый HTML отправится автоматически; HTML/JSON доступны повторно через пункт **Аналитические отчёты YouTube** в меню бота. Пока связь или доставка выключены, сайт сохраняет отчёты.

Адаптер в `app/Integrations/TelegramBot` получает событие завершения и создаёт доставку `youtube_analytics_report`. Outbox предотвращает повторную отправку. Ошибка уведомления повторяется без пересчёта аналитики. Актуальные права, связь и согласие повторно проверяются перед отправкой документа.

## Запуск

Примените миграции и соберите клиент/SSR:

```bash
php artisan migrate --force
npm run build
```

Нужен настроенный `YOUTUBE_DATA_API_KEY`. Для долговечной очереди:

```dotenv
YOUTUBE_ANALYTICS_REPORTS_QUEUE_CONNECTION=database
YOUTUBE_ANALYTICS_REPORTS_QUEUE=youtube-analytics-reports
YOUTUBE_ANALYTICS_REPORTS_TIMEZONE=Europe/Moscow
YOUTUBE_ANALYTICS_REPORTS_FETCH_MAX_PAGES=100
```

Допустимы `database` и `redis`. `retry_after` должен быть больше timeout задания 120 секунд; штатные 150 секунд подходят. Cache должен поддерживать атомарные блокировки; в production нужен общий постоянный cache.

```bash
php artisan queue:work database --queue=youtube-analytics-reports --timeout=120 --tries=1 --sleep=1 --max-time=3600
```

Worker должен постоянно работать под Supervisor/systemd с перезапуском после выхода. Для локальной проверки можно убрать `--max-time=3600`.

Laravel scheduler вызывает `youtube:analytics-reports-maintain` каждую минуту. На сервере нужен `php artisan schedule:run` каждую минуту, локально — `php artisan schedule:work`. Регистрация проверяется через `php artisan schedule:list`. Пропущенные запуски и зависшие задания восстанавливаются ограниченными партиями; завершённые снимки не пересчитываются.

Для доставки нужен существующий worker `TELEGRAM_BOT_QUEUE`. После изменения конфигурации обновите config cache и перезапустите workers. Автоматические тесты используют изолированную БД, HTTP-подмену YouTube API и fake транспорта бота. Реальная отправка проверяется при развёртывании.
