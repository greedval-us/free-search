# Telegram sessions in MoonShine

## Назначение

Раздел **Операции → Сессии Telegram** подключает сервисные пользовательские аккаунты MadelineProto для существующего поиска, парсеров и отслеживания. Он не относится к боту `defstudio/telegraph`, токенам BotFather или привязке Telegram к аккаунту сайта.

Администраторы создают и продолжают свои подключения. Разработчики видят список и состояние без форм авторизации. Аналитикам раздел недоступен. Даже другой администратор не может продолжить чужую незавершённую авторизацию. Регистрация новых аккаунтов Telegram, перезапись существующих консольных сессий и удаление рабочих сессий не реализованы намеренно.

## Подключение

1. Откройте раздел и задайте новое имя сессии, например `search-secondary`.
2. Введите телефон существующего аккаунта в международном формате с `+`.
3. Введите полученный от Telegram код. Если включена двухэтапная аутентификация, далее появится форма пароля.
4. После подтверждённого входа сессия автоматически попадает в существующий round-robin пул. Новые задания используют её без изменения `.env` и без перезапуска обычных queue workers.

Страница восстанавливает текущий шаг по записи подключения. После сетевого сбоя используйте «Проверить состояние авторизации» перед запросом нового кода. Это особенно важно, если Telegram уже принял код, но HTTP-ответ не дошёл до браузера. Неверный код в установленной версии MadelineProto сбрасывает шаг: интерфейс предлагает повторный запрос через телефон. Неверный пароль 2FA можно ввести повторно.

Попытка действует `madelineproto.admin_auth.ttl_minutes` минут. После истечения срока нужно заново ввести телефон; незавершённая сессия не подключается к пулу автоматически. Ограничение `FLOOD_WAIT` сохраняется в `retry_at` и действует для всех шагов этого подключения. UI не создаёт новый аккаунт, не вызывает `completeSignup` и не пытается обходить ограничения Telegram.

## Хранение и безопасность

- `telegram_session_connections` содержит имя, ID сотрудника, шаг, безопасный код ошибки и временные отметки. Телефон, OTP и пароль туда не записываются.
- Секреты передаются POST-запросами с CSRF, не сохраняются в flash input и не попадают в аудит. В production формы и операции разрешены только через HTTPS. Частота запросов ограничивается Laravel rate limiter.
- MadelineProto хранит собственные данные авторизации в private storage. Эти файлы эквивалентны доступу к аккаунту: не публикуйте их, не включайте в Git и защищайте резервные копии. При подключении создаются файлы с ограниченной Unix-маской доступа.
- Файл `session.<name>.madeline.pending` исключает подключение из пула до подтверждения. Просроченные/прерванные подключения остаются изолированными: удаление каталога сессии или принудительный logout автоматически не выполняются.
- Файловая блокировка защищает каждый шаг и резервирование имени. Консольная команда использует ту же блокировку и не трогает pending-сессии, созданные мастером. Записи аудита содержат только ID сотрудника, переход шага и безопасный код ошибки.
- На время авторизации отключены аргументы исключений и вывод PHP-ошибок в браузер. Для запускаемого MadelineProto IPC-процесса добавляется приватный `auth-php/auth.ini` через `PHP_INI_SCAN_DIR`, с сохранением обычных каталогов конфигурации. SDK-логирование ограничено уровнем NOTICE. Основной `php.ini` и настройки других запросов не изменяются.
- Не включайте запись тел этих запросов в Nginx, APM или отладочных инструментах. Сырые исключения SDK не показываются в интерфейсе.

Состояние «вход подтверждён» относится к последней успешной проверке, а не к постоянному мониторингу Telegram. Для консольных сессий показывается только факт обнаружения на диске, без сетевой проверки при открытии страницы. Если ручная проверка выявит сброшенную авторизацию у созданной здесь сессии, она снова изолируется от пула.

## Развёртывание

```bash
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan queue:restart
```

Перезапуск workers при первом деплое нужен для загрузки новой логики исключения pending-сессий. При последующем добавлении аккаунтов перезапуск не требуется. PHP-FPM и процессы MadelineProto/queue должны работать от одного системного пользователя с правом записи в настроенные private-каталоги сессий и логов. Не запускайте создание новых web-сессий от root через консоль параллельно с мастером.

Для работы нужны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`, расширения и возможность запуска IPC, уже необходимые проекту для MadelineProto. Маршруты учитывают настроенные prefix/domain MoonShine и существующий IP allowlist. Для медленного первичного подключения согласуйте PHP/FPM/Nginx timeout: инициализация и авторизация могут занять несколько десятков секунд. RPC- и connection-timeout заданы в `config/madelineproto.php`; отдельная очередь с незашифрованными OTP/паролями не создаётся.

Используйте короткие имена: Unix-сокеты IPC имеют ограничение длины пути. Дополнительные аккаунты и незавершённые подключения могут создавать процессы MadelineProto и расходовать память. `max_sessions` ограничивает число созданных через панель записей, а не гарантирует достаточность ресурсов VPS; увеличивать его следует после оценки нагрузки. Прерванные подключения можно продолжить под тем же именем.

## Слои и проверки

MoonShine отвечает за страницы, маршруты, формы и роли. `SessionConnectionService` управляет состоянием и аудитом, `SessionFiles` изоляцией и блокировками, `SessionAuthenticator` отделяет сценарий от SDK. `MadelineSessionAuthenticator` использует штатные `phoneLogin`, `completePhoneLogin`, `complete2faLogin`, `getAuthorization`. Консольный вход остаётся доступен.

Feature-тесты используют SQLite и подмену `SessionAuthenticator`, не отправляют коды в Telegram. Проверяются роли, шаги с/без 2FA, восстановление состояния, запрет доступа к чужой попытке, CSRF/HTTPS/throttling, expiry/FLOOD_WAIT, блокировки, отсутствие секретов в HTML/JSON/БД/flash и публикация в пул. Отдельный тест запускает локальный дочерний PHP и проверяет наследование защитных настроек.

Реальный вход и поведение IPC на конкретном VPS нужно проверить вручную с разрешённым сервисным аккаунтом после деплоя. Источники API: [MadelineProto Login](https://docs.madelineproto.xyz/docs/LOGIN.html), [PHP INI scan directories](https://www.php.net/manual/en/configuration.file.php#configuration.file.scan).
